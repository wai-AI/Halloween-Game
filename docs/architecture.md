# Архітектура

## Статичний застосунок

| Файл | Відповідальність |
| --- | --- |
| `site/index.html` | Вивід, командний рядок, приховані оголошення для screen reader та гарбузик-нагадувач |
| `site/tik.svg` | Піксельний маскот для нагадування, передбачення та favicon |
| `site/tik-release.svg`, `site/tik-stay.svg` | Різні статичні Тики для кінцівок: сонний і в навушниках |
| `site/style.css` | Термінальний інтерфейс, адаптивна верстка, режим `embed` |
| `site/story.js` | Завдання, підказки, установлені факти та віртуальні файли |
| `site/engine.js` | Стан, команди, шляхи, відповіді, переходи, нагадування та валідація збережень |
| `site/app.js` | Вивід команд, історія вводу та localStorage |
| `site/game.js` | Згенерований класичний скрипт із трьох модулів вище |
| `scripts/build.mjs` | Збирання без сторонніх залежностей |
| `tests/engine.test.mjs` | Автоматична перевірка ігрової логіки через Node.js test runner |

Сервер, API, база даних та генеративна модель відсутні. Термінал виконує лише власні команди над віртуальною файловою системою. Команди не передаються операційній системі. Гра не надсилає історію команд у мережу.

## Переходи

`stage` має значення від 0 до 4: кількість уже розв’язаних загадок. Кожна правильна відповідь відкриває наступні файли, додає факт і встановлює наступний трихвилинний інтервал. Неправильна відповідь не змінює етап. До `stage=4` фінальні команди недоступні.

При `stage=4` гравець обирає `release` або `stay`. Вибір зберігається в `ending` і не змінюється повторною командою. У кінцівці `stay` створюється віртуальний журнал сеансу 09; це завершення історії, нової п’ятої загадки немає.

Четверта загадка має три умови: власну мітку записано через `echo`, після цього прочитано саме журнал сеансу 08, а в `check` передано цю саму мітку. Нова мітка скасовує попереднє свідчення прочитання. Стан доказу переживає перезавантаження.

Усі репліки ECHO заздалегідь записані у сценарії. Перехід гри лише обирає відповідний архівний текст; новий діалог не генерується.

## Збереження

Ключ localStorage: `dou.haunted-terminal.session07.v1`. Зберігаються етап, кінцівка, робочий каталог, використані підказки, прочитані файли, знайдені приховані файли, історія команд, мітка, журнал поточного сеансу та видимий вивід.

Схема має версію. Пошкоджений чи несумісний запис відхиляється. Невідомі шляхи, типи рядків та зайві поля не потрапляють в інтерфейс. Вивід вставляється через `textContent`.

Історія обмежена 80 командами, журнал — 256 записами, вивід — 160 блоками та приблизно 250 тисячами символів. Нотатки й прогрес не залежать від очищення або скорочення видимого виводу. Після дуже довгого експериментування старі записи журналу можуть зникнути; мітку четвертої загадки можна просто додати знову.

Помилки читання чи запису storage перехоплюються. У такому разі гра працює в пам’яті та виводить службовий рядок про недоступність збереження.

## Тик

Дедлайн зберігається як абсолютний час. Перший нагадувач — через 180 000 ms після початку загадки, наступні — раз на 180 000 ms від попереднього показу. Вкладка у фоні не показує повідомлень; при поверненні прострочений нагадувач може з’явитися. Це не ігровий штраф і не блокування.

Після хоча б однієї підказки на поточному етапі нагадування припиняються до наступної загадки. На фінальному виборі та після кінцівки нагадувань немає. Кнопка закриття та будь-яка непорожня команда ховають гарбузика.

## Адаптивність і доступність

Від 1050 px поруч із терміналом є згортана шпаргалка; на меншій ширині вона стоїть під виводом, над вводом. Вивід прокручується окремо від командного рядка; довгі рядки переносяться в межах вікна. На вузькому екрані prompt стоїть над вводом. Поле має розмір 16 px, без початкового фокусу й примусового відкриття клавіатури.

Немає вкладок, дерева файлів, карток, декоративної шапки чи лічильника етапів. Файли відкриваються через `ls`, `cd`, `cat`. `notes` повертає поточну загадку, встановлені факти та відкриті підказки прямо у виводі. Підтвердження перезапуску теж працює командами: `restart` → `y` / `n`. Інша команда чи перезавантаження скасовує запит.

Текст білий на чорному. Службові рядки сірі, репліки блакитні, успіх — зелений, помилки — рожеві, підказки — жовтогарячі. Новий текст поступово друкується без блокування вводу. Скримерів та мерехтіння немає. Є підписи кнопок, перехід до вводу з клавіатури та прихований status-регіон для screen reader. Старі збереження сумісні з новим інтерфейсом; схему прогресу не скинуто. Ревізія тексту `contentRevision=4` оновлює вступ, умови й нотатки зі збережень ревізії 3 на місці, зберігаючи історію, етап, кінцівку, підказки та мітку. Для старіших ревізій вивід перебудовується. Попередні репліки доступні через `notes`.


## Вивід і фінальний вибір

DOM доповнюється новими рядками; попередні репліки не створюються заново при кожній команді. `clear` і перезапуск перебудовують вивід, а скорочення історії прибирає лише найдавніші вузли. `help` не повторює сюжет. У звичайних файлових логах — метадані повідомлень без повторного відтворення реплік; їх текст доступний через `notes`.

Запис `kind=choices` рендериться як семантична HTML-таблиця з двома колонками, Тиком по центру кожної, описами та командами `release` / `stay`. Керування лишається через командний рядок. Нагадувач має окремі вузли бульбашки та гарбузика; частину гарбузика перекриває край кута. У колонках різні SVG, які також використовує окремий екран завершення.

Автодоповнення враховує позицію курсора, зберігає решту рядка, підтримує абсолютні й відносні шляхи. Явний префікс `.` дозволяє доповнювати прихований файл без попереднього `ls -a`, як у звичайному shell. Tab обробляється у вводі; Shift+Tab лишає навігацію клавіатурою.


## Передбачення, друк і завершення

`pumpkin` повертає окрему дію інтерфейсу, не змінює загадку, підказки або доказ четвертого етапу. Передбачення випадково обирається з `FORTUNES` без повторення попереднього. Позиція випадкова, обмежена розмірами iframe й верхнім краєм командного рядка. Перераховується при зміні розміру. Дія не запускає нових таймерів і не впливає на трихвилинний нагадувач.

Друк змінює лише текстові DOM-вузли вже створених рядків, зберігаючи кольори й семантику таблиці. Повний стан зберігається до початку ефекту. Один виклик обмежено 1800 ms; будь-яка нова команда завершує попередній ефект синхронно. Відновлений вивід не анімується. Є пропуск, постійний перемикач (`dou.haunted-terminal.typing`), автоматичне вимкнення при `prefers-reduced-motion` і завершення при переході вкладки у фон.

Екран завершення формується зі збереженого `ending`, а не залежить від наявності останнього рядка у transcript. Він показує привітання, назву кінцівки, її наслідок, стан ECHO й відповідного Тика. Термінал можна переглянути та повернутися до підсумку; кнопка повторної гри виконує звичайний `restart` із підтвердженням `y/n`.


## Фокус вводу

Клік у неінтерактивній частині `#app` переводить фокус до команди з `preventScroll`. Виділений текст зберігається, кнопки, посилання й інші поля не перехоплюються. Коли фокус у виводі, друкований символ переводить фокус до команди й вставляється один раз у поточну позицію курсора з урахуванням maxlength; Enter виконує набрану команду. Ctrl/Meta/Alt-комбінації, прокрутка й навігація залишаються браузеру. Обробники діють лише всередині гри та вимкнені на фінальному екрані. Початкового автофокусу немає.

У збереженні є `reminderIntervalMs=180000`. Для попередніх збережень дедлайн переноситься з п’яти на три хвилини зі збереженням минулого часу; уже прострочене нагадування стає доступним одразу.


## Шпаргалка та початок гри

Нативний `details#command-guide` відкритий за замовчуванням, керується мишею та Enter/Space. Вибір зберігається окремим ключем `dou.haunted-terminal.commands`, без зміни підказок чи прогресу. У вузькому iframe тіло шпаргалки має власну прокрутку та обмежену висоту; вивід і поле команд залишаються доступними. На фінальному екрані весь terminal-workspace приховується. Обробники фокусу не перехоплюють summary та виділення тексту. Звичайний клік на текст шпаргалки повертає фокус до команди. ResizeObserver тримає нагадування й кнопку пропуску друку над виводом після зміни розміру чи згортання.

Історія команд рендериться двома текстовими вузлами: бірюзовий префікс guest@echo та білий ввід. Вставлення залишається через textContent, HTML з команд не виконується.

Початкові приклади навчають відкривати папки та читати файли; умови загадок вказують доступні місця пошуку. `notes` відновлює умову після clear. Четверта умова показує, де прочитати конфігурацію ECHO, але не розкриває послідовність власного доказу. Помилки відрізняють файл від папки, дають виправлену команду й не розкривають ще закриті ресурси.
