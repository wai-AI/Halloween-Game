# Haunted Terminal: Session 07

Браузерна геловінська гра для спільноти DOU. Чотири загадки, віртуальна файлова система та дві кінцівки. HTML, CSS і JavaScript; без бекенду, зовнішніх шрифтів, бібліотек чи мережевих сервісів гри.

Інтерфейс — чорно-білий термінал без шапки, вкладок, карток, бічних панелей та індикаторів прогресу. Один жовтогарячий акцент позначає службові й сюжетні повідомлення, підказки та Тика. Файли й нотатки доступні командами.

## Запуск

Готові файли лежать у `site/`. Можна відкрити `site/index.html` у браузері. Для перевірки в локальному HTTP-середовищі з кореня проєкту:

```sh
python3 -m http.server 8000 --directory site
```

Відкрий `http://localhost:8000/`. Проходження зберігається в поточному браузері. Збереження при відкритті через `file://` залежить від браузера; HTTP-запуск надійніший.

## GitHub Pages

1. Створи репозиторій і завантаж увесь вміст цього проєкту, включно з `.github/workflows/pages.yml`. Основна гілка в конфігурації — `main`.
2. У **Settings → Pages → Build and deployment → Source** обери **GitHub Actions**.
3. Дочекайся успішного workflow **Deploy GitHub Pages**. Його можна запустити вручну через **Actions → Deploy GitHub Pages → Run workflow**.
4. Відкрий адресу, яку повернув deployment. У Pages публікується лише папка `site/`.

Workflow спочатку запускає тести, потім збирає `game.js` і публікує статичні файли. Залежностей для встановлення немає. Всі посилання на ресурси відносні, тому гра працює і в підкаталозі `/repository-name/`.

Інструкція спирається на [документацію GitHub про власні workflows Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) та [вибір джерела публікації](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Цільовий репозиторій: https://github.com/wai-AI/Halloween-Game. Публікація налаштована через workflow GitHub Actions.

## Вбудовування на DOU

Після публікації заміни URL у прикладі на фактичну адресу гри:

```html
<iframe
  src="https://wai-ai.github.io/Halloween-Game/?embed=1"
  title="Haunted Terminal: Session 07 — гра DOU"
  width="100%"
  height="760"
  style="display:block;width:100%;height:760px;border:0"
  loading="lazy"
></iframe>
```

Термінал займає всю висоту вікна або iframe. `?embed=1` зменшує зовнішні відступи. Ширина — від 320 px. За потреби можна використати `sandbox="allow-scripts allow-same-origin"`: збереження працюватиме, якщо його дозволяє браузер. Для гри не потрібні камера, мікрофон, fullscreen, буфер обміну, popups чи надсилання форм. Відсутність дозволу `allow-forms` не блокує ввід команд.

У суворому sandbox без `allow-same-origin` збереження недоступне. Гра повідомляє про це й продовжує працювати в пам’яті. Завантаження ресурсів у такому sandbox також залежить від заголовків хостингу; рекомендований варіант — звичайний iframe або варіант вище. Блокування стороннього storage у браузері теж може вимкнути збереження. Корисно додати поруч звичайне посилання «Відкрити гру окремо».

Сам код iframe перевірено локально. Вбудовування в опублікований допис DOU ще не перевірено: редактор чи політика сайту можуть вимагати дозволу на зовнішній iframe.

## Керування

`help`, `ls`, `ls -a`, `cd`, `pwd`, `cat`, `check`, `echo`, `hint`, `notes`, `clear`, `restart`. Кінцеві команди — `release` та `stay`.

- Дві підказки на кожну загадку. Відкриті підказки можна перечитати через `notes`.
- Тик нагадує про `hint` раз на п’ять хвилин, якщо поточна загадка ще не розв’язана й для неї не відкривали підказку. Будь-яка непорожня команда ховає нагадування.
- `notes` показує лише встановлені факти, відкриті підказки та зроблений фінальний вибір.
- `Tab` доповнює команду або шлях; `↑` / `↓` переглядають історію команд.
- `clear` очищує екран; прогрес зберігається.
- `restart` запитує підтвердження прямо в терміналі. `y` починає нове проходження; будь-яка інша команда скасовує запит. Перезавантаження теж скасовує непідтверджений запит.
- Після кінцівки архів можна перечитувати. Для іншого вибору потрібно нове проходження.

Немає штучних затримок, зависань, звуків, скримерів, мерехтіння чи прихованого відліку до програшу.

## Редагування й перевірка

Потрібен Node.js 22 або новіший. Команду `npm install` запускати не потрібно.

```sh
npm test
npm run build
```

Редагуй `site/story.js`, `site/engine.js`, `site/app.js`, `site/index.html` та `site/style.css`. Після змін JavaScript виконай `npm run build`. Браузер завантажує готовий `site/game.js`; він генерується з трьох модулів, і вручну його редагувати не треба. Класичний скрипт використано для сумісності з локальним запуском та iframe.

`npm run qa` створює тимчасову `site/qa.html` з iframe 320, 390 і 768 px, низьким вікном та перевіркою заблокованого storage. Після перевірки видали `site/qa.html` перед публікацією.

Архітектура — `docs/architecture.md`. Звірка сюжету та походження текстів — `docs/scenario.md`. Результати перевірок — `docs/testing.md`.
